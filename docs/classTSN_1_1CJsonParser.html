Detailed Description

Clase principal para parsear JSON esta maneja tema de parsing, errores, padding todo lo relacionado a ello.

Flujo tipico: Assing (string) o AssingFile (archivo .json o cache .jsontc), CorrectPadding, Parse y GetRoot para navegar con CJsonNode. Parse recorre el documento una sola vez (O(n), sin recursion) y llena la cinta (tape): los numeros, booleanos y nulls se materializan y los strings y keys se guardan como offset + largo sobre m_raw (se desescapan al leerlos). Los objetos grandes ganan una tabla de hash perfecto bajo demanda (JIT; ver Options y BasesParserSLan\Src\Node\SPEC.md, seccion JIT). Si algo falla: LastErr(), ErrorInfo() (imprime linea y columna) y CatchErr(). Con la DLL (JSONPARSERBYLEO_DLL) existen ParseSimd y CorrectPaddingSimd. El cache compilado se guarda con SaveCompiled y se carga con AssingFile (heredados de CBaseStructuredLan).

Warning
Los nodos (CJsonNode) apuntan a la cinta de este parser: dejan de ser validos con el siguiente Assing / AssingFile / Parse.

bool TSN::CJsonParser::AutoParseByFileExt ( const int file_ext_type)

AutoParseo en base a una extension de archivo valida (TSN_SLF_EXT_TYPE_FILE o TSN_SLF_EXT_TYPE_CACHE_FILE).

Esta funcion escoje automaticamente en base a la extension que emtodos llamar si rawfile o embeded Pensada para encadenarse con AssingFile: parser.AutoParseByFileExt(parser.AssingFile(nombre, common)).

  • texto (.json y cualquier extension que no sea .jsontc): llama CorrectPadding y Parse;
  • cache compilado (.jsontc): ya viene parseado, solo comprueba que haya cinta y texto;
  • cualquier otro valor (por ejemplo el -1 de AssingFile cuando no pudo abrir el archivo): error TSN_JSON_ERR_INVALID_EXT_FILE.

void TSN::CJsonParser::CatchErr ( )

Completa m_last_err con los errores que el camino rapido de Parse no deja escritos.

Son 4: true / false / null mal formados (TSN_JSON_ERR_MALFORMED_*) y un token invalido (TSN_JSON_ERR_INVALID_CHAR). Se deducen del ultimo token leido. Si m_last_err ya tiene valor no hace nada. Tambien acota m_pos a m_len - 1.

Note
Llamar cuando Parse devuelva false y se vaya a leer LastErr() directamente; ErrorInfo ya la llama por ti.

◆ CorrectPadding()

void TSN::CJsonParser::CorrectPadding ( )

Corrige el padding de raw agregandole mas bytes y centinelas al final.

Warning
Debe de llamar siempre este metodo antes de Parse (no hace falta con AutoParseByFileExt, que ya lo llama)

Agrega 11 bytes tras los m_len del documento: un espacio, un caracter invalido ('^'), comillas y algunos centinelas mas. Parse no comprueba limites en su camino rapido: con esos centinelas un json truncado (llave o corchete sin cerrar, string sin cerrar, \\endiskip final) cae en un error de malformacion en vez de leer fuera del arreglo. Es tambien el padding que asume CBSFLUnescape.

Note
Cambia el tamaño de m_raw pero NO m_len (el contenido sigue siendo m_len bytes). Si el documento es mas grande que la reserva de la cinta, la agranda. Si llenas m_raw a mano, llama antes a CalcLen(). Se puede repetir sin problema (reparsear sin volver a copiar).

◆ Parse()

bool TSN::CJsonParser::Parse ( )

Funcion principal de parse, no recibe ningun parametro.

Hace falta llamar a CorrectPadding\Assing antes esta funcion solo parsea y llean intemnte su cinta, ud tiene que llenar el buffer y corregir su padding

Returns
true en caso de exito false si fallo algo consulte LastErr()

Reinicia el estado (error, posicion, cinta y tablas de hash) y recorre m_raw una sola vez.

Note
La raiz debe ser un objeto o un array: un valor suelto en la raiz (un numero, un string...) da error. Los enteros o reales que no se pueden representar exactos se guardan como STRING (ver CJsonNode::ToString / ToDouble). Se puede llamar varias veces sobre el mismo m_raw.
Warning
Requiere CorrectPadding().
