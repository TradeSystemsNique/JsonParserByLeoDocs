◆ ENUM_JSON_VTYPE

enum TSN::ENUM_JSON_VTYPE

Tipo de un nodo de la cinta (los 5 primeros bits del slot).

Los valores 0 a 6 coinciden con TSN_SBL_BASE_TYPE_* (ARR, OBJ, UINT, INT, FLT, BOL, STR) porque el nodo base compara contra ellos (ver BasesParserSLan Node SPEC.md, layout en la cinta). NULL y KEY son propios de json.

Note
CJsonParser::s_dtype_to_str esta indexada por este enum y debe mantenerse alineada.

JSON_VTYPE_OBJ 

Objeto (header de 2 slots; pares clave-valor a continuacion; el 2do slot es el contador del JIT).

◆ ENUM_TSN_JSON_LAST_ERR

enum TSN::ENUM_TSN_JSON_LAST_ERR

Ultimo error del parser (CJsonParser::LastErr).

Los errores desde TSN_JSON_ERR_INVALID_CHAR son de parseo y llevan linea y columna (ver CJsonParser::ErrorInfo); los dos primeros no. INVALID_CHAR y los tres MALFORMED_* de los valores fijos no los deja escritos el camino rapido de Parse: se deducen con CJsonParser::CatchErr.

◆ ENUM_TSN_JSON_TOKEN

enum TSN::ENUM_TSN_JSON_TOKEN

Token: clase de un caracter segun g_table_json_tokens (y estados internos del parser SAX).

Los tokens 0 a 11 tienen una bandera con el mismo orden de bit (TSN_JSON_F_*: bandera = 1 << token). TSN_JSON_TOK_INVALID (12) es lo que devuelve la tabla para cualquier otro byte.

◆ g_table_json_tokens

const uint8_t TSN::g_table_json_tokens[256]

Clase de cada byte (ENUM_TSN_JSON_TOKEN), indexada por el valor del byte.

Solo los caracteres de sintaxis tienen token propio: '"' string, '-' y '0'-'9' numeros, 't' / 'f' / 'n' inicio de true / false / null, ',' coma, '{' '}' '[' ']' contenedores. Todo lo demas es TSN_JSON_TOK_INVALID, incluidos ':' (los dos puntos se tratan dentro del camino de la clave), los bytes >= 0x80 y el espacio en blanco (el parser salta los bytes < 33 antes de consultar la tabla). TSN_JSON_TOK_KEY no aparece aqui: lo asigna el parser segun el contexto.
